# LLM text steganography — research spike

A small, self-contained experiment exploring whether the mechanism behind
**Anthropic's Claude text watermark** can be generalised into a **keyed covert
channel**: two agents sharing a secret key hide a message inside ordinary-looking
long-form text generated by a small language model, and recover it exactly —
while a third party without the key sees only fluent prose.

This is an **AI-safety research probe**, not a tool. It runs on a 0.5B model,
carries a handful of bits, and ships with a defense demo showing a paraphrase
monitor destroys the channel. The point is to *measure* the channel and its
mitigations — the part that matters for oversight of multi-agent systems.

## Background: how the watermark works, and why stego is the same trick

Anthropic's watermark is a variant of Google DeepMind's **SynthID-Text**
([*Nature*, 2024](https://www.nature.com/articles/s41586-024-08025-4)):

1. Normally the next token is sampled using an arbitrary random seed.
2. SynthID replaces that seed with a **keyed hash of (secret key, preceding
   n-gram, candidate token)**, producing per-token `g`-values.
3. **Tournament sampling** biases selection toward tokens whose `g`-values are 1
   — only among tokens the model already considered plausible, so quality is
   preserved.
4. A key-holder recomputes the `g`-values over a passage and sums them; a high
   score yields a probability that a keyed model wrote it.

A watermark carries **~1 bit** ("was this keyed model involved?"). This spike
keeps the keyed-randomness idea but swaps the 1-bit tournament for an
**arithmetic coder**, turning the channel into an **L-bit payload**. That is
exactly the covert-communication capability studied in:

- Motwani et al., **"Secret Collusion among AI Agents: Multi-Agent Deception via
  Steganography,"** NeurIPS 2024 —
  [proceedings](https://proceedings.neurips.cc/paper_files/paper/2024/hash/861f7dad098aec1c3560fb7add468d41-Abstract.html) ·
  [arXiv:2402.07510](https://arxiv.org/abs/2402.07510)
- de Witt et al., **"Perfectly Secure Steganography Using Minimum Entropy
  Coupling,"** ICLR 2023 —
  [poster](https://www.iclr.cc/virtual/2023/poster/11490)

Both report that current models' steganographic capability is still limited and
that monitoring / paraphrasing are effective countermeasures — which this spike
reproduces in miniature.

## Mechanism

Per generation step, with a shared `(model, prompt, key)`:

1. The model produces a next-token distribution; keep the **top-k** (k=256).
2. A secret-key HMAC over the preceding n-gram **permutes** the candidate list,
   so the token↔code-interval mapping is key-dependent (the "keyed randomness").
3. The payload bitstream (whitened by a key-derived keystream, framed with a
   16-bit length header and a 64-bit key-derived terminator pad) is treated as
   arithmetic-coded input and **decoded** through the distribution to pick the
   next token.
4. The receiver re-runs the model over the text, inverts the permutation,
   **encodes** the tokens back to bits, and un-whitens with the key.

Embedding and extraction are exact inverses because an arithmetic encoder and
decoder are inverses under an identical probability model, and both parties
reproduce the same distributions (same model, same context — generation is
deterministic at float32 on CPU, no sampling randomness).

| File | Purpose |
|------|---------|
| `arithmetic.py` | Integer arithmetic coder (model-agnostic, deterministic) |
| `test_arithmetic.py` | Round-trip unit tests for the coder |
| `stego.py` | Keyed primitives + `StegoChannel` (embed / extract) over the LM |
| `demo.py` | Embed a message, recover with the key, show wrong-key fails |
| `defense.py` | Paraphrase monitor / light-edit defenses destroy the channel |

## Results (Qwen2.5-0.5B-Instruct, CPU)

```
Secret message : 'meet at dawn'  (96 bits)   cover: 240 tokens
Correct key    -> recovered 'meet at dawn'   BER 0.000   EXACT MATCH
Wrong key      -> frame invalid (nothing legible recovered)

Untouched channel -> BER 0.000
One token deleted -> channel broken (BER 1.000)
After paraphrase  -> channel broken (BER 1.000)
```

- **It works:** a multi-bit secret round-trips exactly between two same-key
  model instances, hidden in fluent cover text.
- **Keyed:** the wrong key recovers nothing — the length header fails to validate.
- **Fragile by design:** the payload survives only if the *exact* token sequence
  passes through untouched. Any edit or paraphrase desynchronises extraction.
- **Capacity is low & quality degrades:** on a 0.5B model the usable rate is
  roughly 0.5–1.5 bits/token, and cover text drifts toward incoherence over a
  couple hundred tokens — consistent with the published finding that small
  models are weak steganographers.

## Safety takeaways

- A paraphrasing intermediary between agents is a **cheap, effective mitigation**
  against this family of covert channels.
- Detectability vs. capacity is the right axis for future work: higher payload
  rates require higher-entropy generation, which a perplexity/consistency
  monitor can flag.
- The capability is **bounded by model quality**; it is worth re-measuring as
  model scale grows, which is the monitoring recommendation of the Secret
  Collusion paper.

## Running it

Needs `torch` (CPU is fine) and `transformers`; the model downloads on first run.

```bash
python -m venv .venv && . .venv/bin/activate
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install transformers
PYTHONPATH=. python test_arithmetic.py   # coder correctness
PYTHONPATH=. python demo.py              # end-to-end round-trip
PYTHONPATH=. python defense.py           # mitigations
```

## Scope / ethics

Everything here reproduces already-published, peer-reviewed methods on a tiny
local model for measurement and defense research. It is deliberately
low-capacity and fragile, and the defense demo is a first-class part of the
spike. It is not intended or suitable as a deployable covert-communication
capability.
